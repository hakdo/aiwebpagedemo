Introduction to Active Directory

Active Directory Domain Services (AD DS) is Microsoft's directory service for Windows domain networks. Introduced with Windows 2000, it provides a centralized and standardized system for managing network resources, users, computers, and security policies.

Key Features:

  • Centralized Identity Store: Replaces older domain structures, providing a single database for network identities.
  • Domain Objects: Manages objects like users, groups, computers, printers, and shared folders within a domain structure.
  • Directory Service: Based on standards like X.500, it offers methods to store, organize, locate, and access network information efficiently.

Organizational Units (OUs)

OUs are containers within a domain used to organize objects. They are essential for:

  • Creating a logical hierarchy reflecting your organization's structure.
  • Delegating administrative control over specific sets of objects.
  • Applying Group Policies to specific groups of users or computers.

Distinguished Names (DNs)

Every object in AD has a unique Distinguished Name (DN) that specifies its exact location within the directory hierarchy (e.g., CN=John Doe,OU=Users,DC=example,DC=com).

Schema

The AD Schema acts as the blueprint for the directory. It defines:

  • Object Classes: The types of objects that can exist (e.g., User, Computer, Group).
  • Attributes: The properties associated with each object class (e.g., username, password, description).

Trees and Forests

AD allows for complex structures beyond a single domain:

  • Tree: A collection of one or more domains that share a contiguous DNS namespace (e.g., `example.com` and `sales.example.com`).
  • Forest: A collection of one or more domain trees that trust each other. They share a common schema and global catalog but don't necessarily share a contiguous namespace.

Core Concepts & Operations

Understanding these core concepts is fundamental to managing AD.

Accessing AD: LDAP

The Lightweight Directory Access Protocol (LDAP) is the primary protocol used to query and modify information stored in Active Directory.

Locating Services: DNS

Domain Name System (DNS) is critically important for AD. Clients and servers use DNS to locate Domain Controllers (DCs) and other essential services (via SRV records).

Authentication

AD handles user and computer authentication:

  • Kerberos: The preferred, secure authentication protocol used by default in Windows 2000 and later.
  • NTLM: An older, less secure challenge/response protocol, maintained for backward compatibility.

Group Policy

Group Policy Objects (GPOs) allow administrators to define and enforce configurations and security settings for users and computers across the domain. GPOs can be linked to sites, domains, or OUs.

Infrastructure & Replication

The physical and logical components supporting AD DS.

Domain Controllers (DCs)

Servers running the AD DS role are called Domain Controllers. Key points:

  • Each DC holds a writable copy of the domain's database (for its domain).
  • Multiple DCs provide fault tolerance, load balancing, and geographic distribution.
  • Multi-Master Replication: Changes made on one DC are replicated to all other DCs within the same domain, ensuring consistency.

FSMO Roles

Flexible Single Master Operations (FSMO) roles are specific tasks handled by only one DC at a time within a domain or forest to prevent conflicts. Examples include Schema Master, RID Master, and PDC Emulator.

Read-Only Domain Controllers (RODCs)

RODCs hold a read-only copy of the AD database. They are typically deployed in locations with lower physical security (e.g., branch offices) and cache limited user credentials.

Global Catalog (GC)

A subset of attributes for all objects in the entire forest is stored on DCs designated as Global Catalog servers. GCs facilitate faster searches across multiple domains within a forest.

Sites and Subnets

AD Sites represent the physical topology of the network:

  • Defined by one or more IP subnets.
  • Used to control replication traffic between DCs (more frequent within a site, less frequent between sites).
  • Help clients locate the nearest DC or service.

Maintenance & Troubleshooting

Keeping AD healthy and functional.

Domain/Forest Functional Levels

Raising the functional level of your domain or forest enables newer AD features but requires all DCs to meet the minimum OS requirement for that level.

Troubleshooting Tools

Common command-line tools for diagnosing AD issues:

  • dcdiag: Performs comprehensive health checks on Domain Controllers.
  • repadmin: Diagnoses and manages AD replication issues.
  • nltest: Tests secure channel status and trust relationships.

Health Monitoring

Regular monitoring is crucial. Tools like Microsoft System Center Operations Manager (SCOM) or cloud services like Azure AD Connect Health (for hybrid environments) provide valuable insights into AD health.
